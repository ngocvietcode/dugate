Section 04

Profile & Multi-Tenant Model

Each API consumer (tenant) is governed by a Profile — a per-endpoint configuration layer that controls access permissions, parameter defaults, pipeline routing, and cost governance. A single deployment serves all tenants with differentiated behavior.

Controlled Parameters

Administrators define default parameter values and designate which parameters are locked (immutable by clients) vs. open (client-overridable). This ensures sensitive configurations remain under central control.

Per-Tenant Pipeline Routing

The same logical endpoint (e.g. /extract:invoice) can route through different AI models for different tenants. Administrators configure routing overrides per profile without additional deployments.

Hierarchical Resolution

Profile lookup resolves from the most specific scope (e.g. "extract:invoice") and falls back to service-level ("extract") when no specific configuration exists. This supports both broad defaults and targeted overrides.

User-to-Profile Mapping

Interactive users are assigned to one or more profiles. All operations submitted through the web interface inherit the same access rules, quotas, and routing as API-based consumers.

Prompt Management

Template Variables

All prompts support dynamic placeholders that are populated from registry defaults, profile parameters, and client inputs at runtime. This decouples prompt logic from hardcoded values.

Document Type Presets

Each recognized document type (invoice, contract, ID card, etc.) carries a predefined extraction schema. Clients may use the built-in schema or supply a fully custom one for ad-hoc use cases.

Section 06

Pipeline Engine

The Pipeline Engine orchestrates multi-step document processing by chaining External API Connections. Standard endpoints use a declarative linear pipeline, while advanced use cases leverage a code-driven Workflow Engine for conditional logic and parallel execution.

Checkpoint & Resume

Each completed step is persisted. On retry (infrastructure failure, timeout), the pipeline resumes from the last successful checkpoint — avoiding redundant AI calls and associated costs.

Workload Isolation

Tenants can be assigned to dedicated worker groups with independent queues and concurrency limits, ensuring high-priority workloads are not impacted by batch processing from other tenants.
