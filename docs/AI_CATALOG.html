Vai trò & hiệu quả

AI SkillHub là nền tảng năng lực AI, tổ chức theo các nhóm skill; Document Skills (phạm vi tài liệu này) là một nhóm con chuyên xử lý tài liệu. Nhóm này đóng vai trò lớp trung gian (gateway) giữa ứng dụng nghiệp vụ và các dịch vụ OCR/LLM/parse: thay vì mỗi ứng dụng tự tích hợp rời rạc, chúng gọi một bộ API đồng nhất; phần phức tạp (định tuyến model, prompt, hàng đợi, chi phí) được tập trung và cấu hình tại hub.

1. Skills & Orchestration

Nhóm Document Skills của AI SkillHub cung cấp 5 primitive skill xử lý tài liệu. Mỗi skill là một lời gọi HTTP độc lập, tham số có kiểu, và được liệt kê máy-đọc-được qua GET /api/v1/services — ở chế độ agentic, mỗi skill đóng vai trò một tool để LLM gọi.

Giải pháp cho một nghiệp vụ là sự điều phối nhiều skill. Điều phối có ba chế độ, dùng chung cùng một bộ skill:

Cùng một bộ 5 skill, ba cách điều phối. Khác biệt là ai quyết định thứ tự gọi và nơi điều phối chạy.

Chế độAi quyết định thứ tự gọiDùng khiTrạng thái
Client tự ghépMã phía client (gọi tuần tự + polling)Luồng ngắn, client tự kiểm soátSẵn dùng
WorkflowDAG định nghĩa trước, chạy server-sideCần xác định, kiểm soát, audit, checkpoint/HITLSẵn dùng
AgenticLLM chọn skill động theo đầu vàoĐầu vào biến thiên/mở, không cố định luồngSkill đã sẵn sàng làm tool (manifest qua /services); runtime agent là hướng mở rộng

Workflow và "client tự ghép" đều là composition — chỉ khác nơi chạy điều phối. Cả ba chế độ tái dùng đúng 5 skill dưới đây, nên thêm skill mới hoặc đổi chế độ điều phối không ảnh hưởng lẫn nhau.

Mỗi skill là một đơn vị độc lập, gọi được riêng lẻ. Hệ thống tiêu thụ có thể gọi ngay một skill đơn lẻ để đáp ứng đúng nhu cầu tại một bước (ví dụ chỉ cần extract hoặc chỉ cần compare), và tự điều phối flow nhiều bước ở phía mình — quyết định gọi skill nào, thứ tự nào, xử lý kết quả trung gian theo logic riêng. Không bắt buộc dùng Workflow; Workflow chỉ là tuỳ chọn khi muốn đẩy phần điều phối (và checkpoint/HITL) sang server-side.

2. Cách gọi API

Mọi skill dùng multipart/form-data: nạp file qua file / files[] (hoặc file_urls JSON), kèm tham số định tuyến và tham số tuỳ chọn. Xác thực qua header x-api-key.

# Đồng bộ — chờ kết quả (file nhỏ)
curl -X POST "{host}/api/v2/docs/{skill}?sync=true" \
  -H "x-api-key: dg_xxx" -F "file=@input.pdf" -F "{discriminator}={sub-case}"

# Bất đồng bộ — nhận 202 + Operation-Location, rồi poll
curl -X POST "{host}/api/v2/docs/{skill}" -H "x-api-key: dg_xxx" -F "file=@input.pdf" -F "{discriminator}={sub-case}"
curl "{host}/api/v1/operations/op-123" -H "x-api-key: dg_xxx"

Bất đồng bộ trả 202 + header Operation-Location; client poll theo URL đó hoặc nhận webhook_url khi xong. Header idempotency-key chống gửi trùng; output_format nhận json/md/html/csv.

3. extract — trích xuất dữ liệu có cấu trúc

📥
POST /api/v2/docs/extract
Định tuyến: type · trả về JSON

Biến tài liệu phi cấu trúc thành JSON. Hai cơ chế độc lập lĩnh vực và một tập preset cấu hình được:

typeNăng lực
customSchema động: truyền fields hoặc JSON schema, trích xuất đúng cấu trúc yêu cầu
queryHỏi đáp trên tài liệu: truyền query, nhận câu trả lời trích từ nội dung
preset typesLoại tinh chỉnh sẵn, mỗi loại có bộ trường cố định; bật/tắt theo Profile

Preset hiện cấu hình: disbursement, guarantee, approval, collateral, credit-report, contract, table, payment-order, lc, invoice, business-license, account-form, id-card, civil-doc, vehicle-doc, insurance. Lĩnh vực mới dùng custom/schema hoặc khai báo preset mới ở cấu hình.

Đầu vào: PDF, ảnh, DOCX; thêm Excel cho dữ liệu dạng bảng.

8. Điều phối & composition

Hệ thống tiêu thụ tự ghép skill ở phía mình: gọi từng skill theo nhu cầu mỗi bước, dùng kết quả của bước trước làm đầu vào bước sau, và áp logic điều khiển (rẽ nhánh, lặp, lọc) theo nghiệp vụ riêng. Một số mẫu ghép (độc lập lĩnh vực):

extract → compare  // bóc tách rồi đối chiếu với dữ liệu tham chiếu
extract → analyze → generate  // bóc tách → đánh giá → sinh báo cáo
transform(split) → extract[parallel] → compare → generate  // tách → bóc tách song song → đối chiếu → tổng hợp
extract(query) → generate  // hỏi đáp rồi soạn phản hồi

Engine điều phối server-side hỗ trợ:

Năng lựcMô tả
Tuần tự / song songNối tiếp các bước, hoặc fan-out N tài liệu xử lý đồng thời
Checkpoint / resumeLưu trạng thái sau mỗi bước; chạy lại từ điểm dừng
Human-in-the-loopTạm dừng cho người duyệt/chỉnh, rồi tiếp tục
Prompt override theo bước3 tầng: prompt code < override theo Profile < default connector
Session chainingTruyền kết quả bước trước làm đầu vào bước sau

9. Workflows

Workflow là một composition đóng gói chạy server-side trên engine ở mục 8: POST /api/v2/docs/workflows, định tuyến qua process, yêu cầu API Key. Mỗi workflow lắp từ các skill ở mục 3–7; bảng dưới liệt kê cấu phần theo từng bước.

processCấu phần (skill · sub-case theo bước)Đặc tính
disbursementanalyze·classify [//] → extract·* [//] → compare·verify → generate·reportHITL ở bước extract
lc-checkerextract (OCR full-text) → analyze·compliance → generate·reporthybrid OCR + file gốc
payroll-verifyextract·table (OCR) → extract (chuẩn hoá) → compare·verify (rule-based)quality gate + retry
structure-compareextract (OCR layout) → extract (cấu trúc) → compare·semantic (theo mapping)HITL xác nhận mapping
brd-analyzeextract·query (intake) → analyze·quality (scorecard) → generate·reportchấm điểm theo scorecard

[//] = chạy song song theo từng file. Một workflow không phải năng lực mới — nó là một cách ghép các skill có sẵn, đóng gói để tái dùng khi luồng lặp lại và cần checkpoint/HITL.

12. Profile & bảo mật

Mỗi API Key là một Profile. Hành vi skill/workflow điều khiển theo Profile, không cần client sửa code — đây là cơ chế để cùng một catalog phục vụ nhiều lĩnh vực.

Cơ chếMô tả
Bật/tắt endpointEnable/disable từng skill·sub-case cho mỗi API Key
Khoá tham sốÉp giá trị mặc định, chặn client override
Override routing/promptĐịnh tuyến connector & prompt riêng theo Profile/bước
Job priorityLOW / MEDIUM / HIGH cho hàng đợi
Rate limitMặc định hệ thống; cấu hình riêng rateLimitPerMin mỗi API Key
Spending limitHạn mức chi tiêu theo API Key; vượt trả 402
Bảo mậtHash API key, mã hoá secret (AES-256-GCM), SSRF protection, từ chối file macro

Onboarding một lĩnh vực mới

  1. Chọn skill·sub-case cần bật.
  2. Khai báo schema cho extract·custom hoặc thêm preset.
  3. Khoá tham số nội bộ; đặt rateLimitPerMin và spendingLimit.
  4. Định tuyến connector AI backend.
  5. Đóng gói Workflow nếu luồng đa bước lặp lại.
